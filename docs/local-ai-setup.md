# 로컬 AI 설치·연결·첫 실행

Line Lens의 AI 목표 조언에는 **앱 서버와 모델 서버, 두 프로세스**가 필요합니다. 웹페이지를 실행하는 `npm start`만으로는 모델이 설치되거나 추론이 시작되지 않습니다. 수동 3D 실험과 CSV 분석은 모델 없이 사용할 수 있습니다.

검수 모델은 CPU에서 실행한 **Qwen3-4B의 Q4_K_M GGUF**이며 서버에 표시한 별칭은 `Qwen3-4B-Q4_K_M`입니다. 이 문서는 Windows PowerShell 기준입니다. 모델 가중치와 llama.cpp 실행 파일은 저장소에 포함하지 않고 자동 다운로드하지 않습니다.

## 1. 앱 소스와 Node.js 준비

Git과 Node.js 22 이상을 설치한 뒤 터미널에서 확인합니다. 로컬 검수 버전은 22.22.2입니다.

```powershell
git --version
node --version
npm --version
git clone https://github.com/Kimhyuntae9665/line-lens.git
cd line-lens
```

이 폴더에 `package.json`이 있어야 합니다. npm 의존성은 별도로 설치하지 않아도 됩니다. 앱을 먼저 `npm start`로 열어 수동 공장 실험이 되는지 확인할 수 있습니다. AI 기능까지 진행할 때는 아래처럼 모델 서버를 별도 터미널에서 실행합니다.

## 2. 모델과 실행 파일 준비

다음 공식 자료에서 사용 중인 운영체제에 맞는 실행 파일과 모델을 준비합니다.

- [llama.cpp 공식 저장소](https://github.com/ggml-org/llama.cpp), [공식 Releases](https://github.com/ggml-org/llama.cpp/releases): `llama-server` 실행 파일과 설치·빌드 안내.
- [Qwen3-4B 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-4B): 원본 모델의 설명과 이용 조건.
- [Qwen3-4B 공식 GGUF 배포 페이지](https://huggingface.co/Qwen/Qwen3-4B-GGUF): llama.cpp에서 읽을 수 있는 GGUF 파일. 파일 목록에서 필요한 양자화 형식을 선택합니다.

**GGUF는 모델 파일 형식이고 Q4_K_M은 가중치 양자화 형식입니다.** 원본 모델 카드와 실제 다운로드한 GGUF의 배포처·파일명은 구분해 확인합니다. 설치할 때 PC의 메모리 여유와 배포처의 요구사항을 확인하세요. 이 프로젝트에서 모든 하드웨어의 최소 메모리나 성능을 측정하지는 않았습니다.

다운로드한 `llama-server.exe`와 함께 필요한 DLL을 같은 실행 폴더에 보관합니다. 모델 파일은 별도 `models` 폴더에 둘 수 있습니다. 다음 예시 경로는 안내용 상대 경로이므로 실제 파일 이름에 맞게 바꾸세요.

```text
모델 실행 폴더/
  llama-server.exe
  [배포본에 함께 들어 있던 DLL 파일]
  models/
    Qwen3-4B-Q4_K_M.gguf
```

모델·실행 파일을 Git 저장소에 추가할 필요는 없습니다. 아래 명령에는 파일 자동 다운로드 옵션이 없습니다.

## 3. 터미널 A에서 모델 서버 실행

`llama-server.exe`가 있는 폴더에서 실행합니다. 아래는 CPU 실행 예시입니다.

```powershell
.\llama-server.exe --model "models/Qwen3-4B-Q4_K_M.gguf" --alias "Qwen3-4B-Q4_K_M" --host 127.0.0.1 --port 8767 --ctx-size 4096 --gpu-layers 0 --reasoning off --reasoning-budget 0 --threads 6 --threads-batch 6
```

| 옵션 | 이 예시에서의 의미 |
|---|---|
| `--model` | 사용자가 준비한 GGUF 파일 경로 |
| `--alias` | 앱에서 확인할 모델 ID; 파일을 다운로드하는 옵션이 아님 |
| `--host 127.0.0.1` | 같은 PC에서만 접속 |
| `--port 8767` | 모델 API의 포트 |
| `--ctx-size 4096` | 이번 구조화 요청에 사용한 문맥 설정 |
| `--gpu-layers 0` | 검수한 CPU 실행 방식 |
| `--reasoning off --reasoning-budget 0` | 이번 짧은 JSON 응답에서 사고 출력을 끈 설정 |
| `--threads 6 --threads-batch 6` | 검수 때 사용한 스레드 수; 모든 PC의 최적값은 아님 |

버전별 지원 옵션은 [llama.cpp 공식 서버 문서](https://github.com/ggml-org/llama.cpp/tree/master/tools/server)와 `llama-server.exe --help`로 확인합니다. 알 수 없는 옵션 오류가 나면 설치한 빌드의 문서·버전을 대조하세요. 임의로 옵션을 바꾸고 같은 검수 환경이라고 표시하지 않습니다. Linux·macOS에서는 실행 파일을 `./llama-server`로 바꿉니다.

모델이 로드될 때까지 기다리고 이 터미널을 유지합니다. 새 터미널에서 확인합니다.

```powershell
Invoke-RestMethod http://127.0.0.1:8767/v1/models
```

`data`의 모델 ID가 보이면 목록 확인에 성공한 것입니다. **이것만으로 목표 해석 추론이 완료된 것은 아닙니다.** 호환 서버는 `/v1/models`와 `/v1/chat/completions` 및 `response_format`의 JSON Schema 구조화 출력을 지원해야 합니다. 일반 채팅만 되는 서버는 작동하지 않을 수 있습니다.

## 4. 터미널 B에서 앱 서버 실행

Line Lens의 `package.json`이 있는 폴더에서 실행합니다.

```powershell
$env:LINE_LENS_LLM_URL = 'http://127.0.0.1:8767/v1'
$env:LINE_LENS_LLM_MODEL = 'Qwen3-4B-Q4_K_M'
npm start
```

두 변수는 코드의 기본값이므로 같은 설정이면 생략할 수 있습니다. [http://127.0.0.1:8765](http://127.0.0.1:8765)를 열고 `AI 목표 조언`의 **실제 로컬 LLM 연결** 표시를 확인합니다. 상태 확인 API도 사용할 수 있습니다.

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/advisor/status
```

정상 연결이면 `reachable:true`, `llmStatus:ready`, 실제 `llmModel`이 반환됩니다. 지정 별칭이 모델 목록에 없으면 서버의 첫 번째 모델 ID를 사용합니다. 환경변수의 이름만으로 실제 로드 모델을 보장하지 않으므로 화면과 `/models`를 함께 확인하세요.

| 변수 | 기본값 | 바꿀 때 확인할 점 |
|---|---|---|
| `PORT` | `8765` | 앱 웹페이지와 `/api/advisor/*`의 포트 |
| `LINE_LENS_LLM_URL` | `http://127.0.0.1:8767/v1` | 모델 API 기본 주소, `/v1` 포함 |
| `LINE_LENS_LLM_MODEL` | `Qwen3-4B-Q4_K_M` | 모델 서버의 실제 별칭과 대조 |

LLM URL은 `http`의 `127.0.0.1`, `localhost`, `::1`만 허용합니다. 외부 호스트·HTTPS·인증정보가 포함된 URL은 거부합니다. API 키는 사용하지 않습니다. 앱이 직접 통신하는 상대는 이 로컬 모델 서버이며, 다른 서버 프로그램 자체의 동작·설정은 그 프로그램의 문서에서 확인합니다.

앱 포트가 겹치면 **터미널 B**에서 먼저 설정합니다.

```powershell
$env:PORT = '8770'
npm start
```

이때 앱·상태 API 주소는 `http://127.0.0.1:8770`이고 모델 주소는 여전히 8767입니다. 두 포트는 다른 역할입니다. 앱 서버를 이미 켰다면 `Ctrl+C`로 종료한 뒤 환경변수를 바꾸고 다시 시작합니다. PowerShell 환경변수는 해당 터미널의 실행 프로세스에 전달됩니다.

## 5. 첫 목표를 요청하고 직접 적용

1. `좀 더 빨리 물량을 만들고 싶어`를 입력하고 `AI에게 목표 해석 요청`을 누릅니다.
2. 수량을 쓰지 않았으므로 양품 1,000은 사용자 요청값이 아닌 시스템 기본값이어야 합니다. 목적·양품량·최소 양품률·공정 변경 수·고정 조건을 읽고 수정합니다.
3. 작업자 모델을 켰으면 가정 피로 40·부하 90%와 인력·속도·휴식 변경 허용도 확인합니다. 이 한도는 안전 기준이 아닙니다.
4. 조건 비교를 누릅니다. 현재 설정에서 서로 다른 작업자 프로필 네 개가 만들어지면 504개이고 중복·변경 금지·작업자 모델 꺼짐이면 수가 줄어듭니다.
5. 후보의 목표 도달 시간·양품량·인원·양품/인시·부담을 읽고 `이 후보를 3D 라인에 적용 ↑`을 누릅니다.
6. 위 3D 화면의 입력값과 결과가 바뀌는지 확인합니다. 기존 재생 시점은 유지합니다. `질문·결과 초기화`는 공장 조건을 유지한 채 AI 질문·결과만 지웁니다.

원문 검증·사용자 확인·126/504개 계산·후보 ID 및 허용 근거 선택은 [AI 동작 설명](ai-workflow.md)에 자세히 있습니다. 목표 해석과 추천 버튼은 실제 LLM을 호출하며, 모델 미연결을 가상 응답으로 대신하지 않습니다.

## 6. 처리 시간과 재현 확인

화면의 **시뮬레이터 계산 시간**과 **AI 목표 해석 / 근거 설명**은 다른 단계입니다. 2026.10.09의 기록된 한 실행에서는 새 계산 4.86초, 목표 해석 34.74초, 후보·허용 근거 선택 63.32초였습니다. LLM 합계 98.06초에 계산과 사용자 확인 시간은 넣지 않았습니다. 평균·보장 시간이 아니며 CPU·모델·요청·캐시에 따라 달라집니다.

[`worker-ai-observed-run.json`](../experiments/worker-ai-observed-run.json)은 실제 모델 연결 관찰 기록입니다. 계산 캐시 사용 시 표시된 조건 수를 새 계산 횟수로 읽지 않습니다. LLM 추론 제한 시간은 각 단계 120초이며 모델 목록 확인은 최대 5초입니다.

```powershell
npm test
npm run benchmark:advisor
```

`npm test`는 계산과 모의 응답 검증이고, `benchmark:advisor`는 LLM 없이 504개 설정의 계산만 재현합니다. `llmCalled:false`를 확인하세요. 두 명령의 통과를 새 실제 모델 실행 성공으로 표시하지 않습니다. 사용이 끝나면 터미널 A·B에서 각각 `Ctrl+C`로 모델·앱 서버를 종료합니다.

## 오류를 구분해 해결하기

| 증상 | 확인 순서 |
|---|---|
| `node`·`npm`·`git`을 찾지 못함 | 설치 여부 확인 → 새 터미널 → 버전 명령 확인 |
| 모델 파일을 열 수 없음 | 터미널 A의 현재 폴더 → GGUF의 실제 파일명 → `--model` 상대 경로 |
| DLL·옵션 오류 | 운영체제에 맞는 배포본과 DLL → 설치 빌드의 `--help` |
| 포트 사용 중 | 모델 포트 8767과 앱 포트 8765 구분 → 해당 프로세스 확인 → 포트를 바꾸면 관련 URL도 수정 |
| 로컬 LLM 미연결 | 터미널 A 실행·로드 완료 → `/v1/models` → 터미널 B의 LLM URL |
| 로컬 AI API 연결 실패 | `npm start`로 실행했는지 → 접속한 앱 포트 → `/api/advisor/status` |
| 120초 제한 초과 | 모델 로그·CPU 사용 확인. 작은 문장으로 다시 실행하고 각 단계 시간을 구분 |
| 구조화 JSON 오류 | 서버의 JSON Schema 지원·모델 출력 완료·로그 확인. 단순 채팅 성공과 구분 |
| 후보·근거 검증 오류 | 허용 ID나 문장 밖의 답을 거부한 상태. 모델·서버 설정을 확인한 뒤 다시 비교 |
| 후보 0건 | 목표 양품·최소 양품률·피로·부하·변경 수·고정값을 직접 확인하고 수정 |
| 공장 조건이 바뀌었음 | 현재 제품·입력값으로 다시 비교한 뒤 적용 |

실패하면 AI 요청은 중단되고 수동 실험·CSV 분석은 유지됩니다. 후보가 없을 때는 LLM 근거 선택을 하지 않습니다. 작은 모델이 원문 없는 숫자나 근거 없는 이유를 만들 수 있어 검증을 제한했지만 사용자 확인을 대체하지 않습니다.

피로·부하는 가정 비교 지표이며 실제 사고확률·안전 인증이나 자유로운 인과 진단을 제공하지 않습니다. [작업자 모델의 계산식·한계](human-factors-model.md), [API 필드·오류 코드](advisor-api.md), [전체 프로젝트 소개](../README.md)와 함께 읽으세요. 별도 CSV 화면의 `AI 검토 프롬프트 .txt`는 다운로드용 텍스트이며 이 서버가 자동 실행하지 않습니다.
