# Line Lens / 풋웨어 생산 손실 분석

창신 LEAN 직무의 **생산 분석 → 운영 지표 관리 → 개선 가정 검토 → 현장 검증 근거 정리** 흐름을 다루는 독립 개인 데모다. 2026.10.07 지원 준비 과정에서 새로 제작했다. Codex의 AI 지원으로 JavaScript 구현·화면·검증 코드를 작성했으며, 회사 생산 시스템에 연동한 도구나 과거 현장 실적이 아니다.

모든 기본 표본은 **합성 데이터**다. 실제 창신 생산 데이터, 내부 문서, 개선 효과 측정값, 증명서 또는 외부 API 비밀값을 사용하지 않는다. 사용자 CSV를 불러오면 `USER_IMPORTED_UNVERIFIED`로 표시하며 유효성 검사 통과를 데이터 사실성 확인으로 취급하지 않는다.

## 직무와 연결한 설계

| 직무 과제 | 데모에서 확인할 동작 | 판단의 한계 |
|---|---|---|
| 시간별 생산 실적 분석 | 계획·총 생산 비교, 시간대 버튼으로 선택 구간 미달 확인 | 여러 작업일·라인의 같은 시간대를 합산한다. 단일 실시간 교대 화면이 아니다. |
| 운영 KPI 관리 | 합계 기준 계획 달성률·양품률, 배치 인시 생산성, 정규화 정지 시간 | 설비 성능 기준속도가 없어 OEE를 주장하지 않는다. |
| 손실 원인과 개선안 검토 | 모든 정지 원인 Pareto, 제품·라인 필터, 선택 원인 감축률 실험 | 정지와 미달의 인과관계는 미확인이다. |
| 개선 효과 검증 | 같은 표본에서 관측 기준과 가정 기반 기대값 비교, 범위 잠금 | 실제 개선 전후 결과가 아니다. 통제 조건과 현장 재측정이 필요하다. |
| AI 활용 지원 | 정의·필터·지문·가정·A3 질문을 Markdown/JSON/프롬프트로 내보내기 | LLM 실행, 예지 모델 학습, AI 자동 원인 판정, API 연동은 없다. |

## 실행

설치할 npm 패키지가 없는 정적 HTML/CSS/ES module 프로젝트다. `file://`로 직접 열면 브라우저가 ES module을 차단할 수 있으므로 로컬 서버를 사용한다.

```powershell
git clone https://github.com/Kimhyuntae9665/line-lens.git
cd line-lens
npm start
```

브라우저에서 `http://127.0.0.1:8765/analysis/index.html`을 연다. 다른 포트를 쓰려면 `$env:PORT = '8768'`을 먼저 설정한다. 서버는 `127.0.0.1`에만 바인딩한다. 분석 도구를 단독 실행하려면 저장소의 `analysis` 폴더에서 `node serve.mjs`를 실행하고 `http://127.0.0.1:8765`를 연다. 또는 저장소 루트에서 Python 기본 서버를 사용할 수 있다.

```powershell
python -X utf8 -m http.server 8765 --bind 127.0.0.1
```

## 확인 순서

1. 초기 화면의 합성 데이터 표시와 240행 표본을 확인한다.
2. 시간대 막대를 선택해 계획·실적·미달 켤레를 확인한다. 정지 원인은 전체 기여 원인과 누적 비율을 표시한다.
3. `LINE-A`와 `FLEX`를 선택한다. 전체 혼합 모델 집계와 분모·물량이 달라지는지 확인한 뒤 `비교 범위 잠금`을 켠다.
4. `자재 대기`를 선택하고 0~80% 감축 가정을 조정한다. 관측 기준과 `SIMULATED` 값을 비교한다. 추가 생산은 각 행의 계획 미달분을 초과하지 않는다.
5. Markdown·JSON·AI 검토용 TXT를 내려받는다. 파일에서 정확한 필터, 정의, 지문, 가정과 A3 질문을 확인한다.
6. CSV를 불러온다. 잘못된 파일은 일부 행을 살려 계산하지 않고 파일 전체를 거부하며 기존 데이터와 비교 조건을 보존한다. 초기화는 합성 표본과 기본 조건을 복원한다.

## 합성 데이터 계약

`sample.csv`는 **3개 가상 라인 × 10개 작업일 × 8개 시간 구간 = 240행**이다. 작업일은 2026.09.14~09.23, 시간은 08~15시다. 제품은 가상 `FLEX`(경량 운동화)와 `CORE`(구조형 워킹화)이며, 모델마다 계획량과 인원이 다르고 라인별 제품 구성도 다르게 만들었다. 실제 제품이나 공정의 표준속도를 뜻하지 않는다.

| 필드 | 단위·의미 |
|---|---|
| `row_id` | 파일 전체에서 유일한 관측 ID |
| `date` | 실제 존재하는 날짜 `YYYY-MM-DD` |
| `line`, `model` | 해당 시간 구간의 라인과 단일 제품 모델 |
| `hour` | 작업 시작 시각의 시, 정수 0~23. 한 행은 한 시간 구간 |
| `planned_pairs` | 총 생산 계획, 켤레 |
| `produced_pairs` | 양품과 불량을 포함한 총 생산, 켤레 |
| `good_pairs` | 양품, 켤레. 총 생산 이하 |
| `workers` | 구간 전체에 배치된 인원, 명 |
| `available_minutes` | 정지 시간을 포함한 배치 시간, 분. 0~60 |
| `downtime_minutes` | 정지 시간, 분. 배치 시간 이하 |
| `downtime_reason` | 행당 하나의 주 정지 원인. 정지 0분이면 `무정지` |

`row_id`와 `date + line + hour`는 각각 유일해야 한다. CSV 인용 필드·쉼표·이스케이프된 큰따옴표·인용 내부 줄바꿈을 처리한다. 모든 필수값은 비어 있을 수 없다. 원본 수치는 유한한 0 이상 안전 정수여야 하며, 잘못된 날짜·시간·양품/생산 관계·정지/배치 관계·전체 구간 정지인데 생산이 있는 행은 거부한다. 추가 열은 계산에 사용하지 않는다. 한 행이라도 검증에 실패하면 파일 전체를 거부한다.

## 계산과 시나리오

- 계획 달성률 = `Σ총 생산 / Σ계획 × 100`
- 양품률 = `Σ양품 / Σ총 생산 × 100`
- 양품 / 배치 인시 = `Σ양품 / Σ(인원 × 배치 분 / 60)`; 정지 시간을 포함한다.
- 정규화 정지 = `Σ정지 분 / Σ총 생산 × 1,000`; 단위는 분/1,000켤레다.
- Pareto는 정지 분을 원인별로 합산하고 모든 기여 원인을 표시한다. 분모가 0인 비율은 `N/A`/JSON `null`이다.

시나리오는 선택 원인의 정지 시간을 설정한 비율만큼 줄일 수 있다고 가정한다. 행별 가동 중 평균 속도는 `총 생산 / (배치 분 − 정지 분)`이다. 추가 생산 기대값은 `min(회복 분 × 평균 속도, max(계획 − 총 생산, 0))`, 추가 양품은 `추가 생산 × 기존 행별 양품률`로 계산한다. 인원과 배치 시간은 불변이다. 가동 시간이 0이거나 생산량이 0인 행은 속도를 추정할 수 없어 추가 생산을 0으로 둔다. 분수 켤레는 기대값이며 원본 생산 개수와 구분한다.

수요·자재·재공품·전후 공정 병목·재작업·품질 변화·안전 제약은 알 수 없다. 제품/행별 추가 물량 비중이 달라지면 집계 양품률도 달라질 수 있다. 계산값은 실제 개선 성과나 인과효과가 아니다. 현장 로그와 동일 조건의 실험·재측정으로 확인해야 한다.

## 재현·테스트

저장소 루트에서 실행한다.

```powershell
node --test analysis/tests/engine.test.mjs
node analysis/generate-results.mjs
```

초점 테스트는 가중 합계 지표, 배치 인시, 혼합 모델 필터, 인용 CSV, 빈값·중복·잘못된 날짜/시간, 수치 관계와 전체 구간 정지 모순, 분모 0, 전체 Pareto, 시나리오 상한·단조 증가·행별 양품률 유지, 원본 인원 불변, 보고서 재현성을 검증한다. 브라우저 화면·다운로드·모바일·키보드 검수는 별도 확인 범위다.

`generate-results.mjs`가 동일한 합성 표본으로 `sample.csv`, `results.json`, `sample-evidence.md`를 다시 만든다. `results.json`은 전체 표본 기본 시나리오(자재 대기 40%)와 FLEX/CORE 비교 근거를 포함한다. 타임스탬프나 난수를 넣지 않아 같은 입력은 같은 결과를 만든다.

기본 표본 지문은 `fnv1a32-71543475`다. 지문은 `row_id`순 정규화 CSV의 Unicode 코드포인트를 처리하는 FNV-1a 32-bit이며 재현 확인용이다. 암호학적 무결성 보증이나 사실성 증거가 아니다.
